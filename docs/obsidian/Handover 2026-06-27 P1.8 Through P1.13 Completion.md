## Key Behaviour Now

- Public reads remain read-only.
- Public event detail preserves raw ticket type `quantity` and adds reservation-aware `availableQuantity`.
- Checkout remains the authoritative availability and payment gate.
- Stale cleanup no longer runs from ordinary read paths; `pnpm stale-orders:process` performs bounded scheduled cleanup.
- Paid webhook fulfilment remains Stripe-driven and transactionally enqueues automatic ticket email outbox jobs.
- Paid-but-unfulfilled orders enter compensation review and emit `paid_but_unfulfilled_compensation_required` on first transition only.
- Tenant-owned object access should return safe 404 for missing and cross-tenant private resources while preserving 401/403/400/409 semantics.
- Operational logs are structured JSON on P1.13-covered paths, with redaction for sensitive keys and alert names emitted as structured `event` values.
- `GET /api/health` exists for external health checks.

## Non-Blocking Gaps To Carry Forward

All current non-blocking items are tracked in [[Non-Blocking Issue Register]]. The most important operational gaps:

- No external metrics backend, alert transport, dashboard, or automatic paging.
- `db_migration_failed` and `app_healthcheck_failed` are reserved/documented names but not emitted by app runtime code.
- Production must route alert event names from logs into real alert channels.
- Production must schedule `pnpm email:outbox:process` and `pnpm stale-orders:process` every 1 minute.
- Email outbox terminal failed jobs need future explicit requeue tooling.
- Compensation-required orders need an operator playbook and, later, controlled review/refund tooling.
- Failed-order timestamp policy and relationship constraints remain audit-only.
- Denormalized ownership drift is tolerated securely at runtime but not repaired.
- Some legacy `console.*` logs remain outside P1.13 migrated surfaces.
- Token-based CSRF is still future design work; trusted-origin compatibility mode remains in place.
- Organisation accounts are shared for MVP; named staff users, MFA, audit logs, and RBAC remain future product/security work.
