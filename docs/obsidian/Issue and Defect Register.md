# Issue and Defect Register

**Owns:** every open defect, accepted risk and external release gate, with its evidence and next action.
**Read when:** you touch an area with an open item, find a defect, or need to know what blocks a real launch.
**Not here:** resolved items ([[Resolved Defects]], search there before opening a new ID); the go-live checklist ([[Pre-hosting Candidate]]).

Statuses: `open`, `accepted-risk`, `external-gate`, `blocked`. Severity: Critical, High, Medium, Low, or Lead (a security finding that depends on a deployment fact).

## Procedure

1. Search this note and [[Resolved Defects]] before opening an item. Reopen a resolved ID here if the same root cause recurs.
2. Record confirmed evidence, user impact, any safe workaround and the next action. No secrets, personal data or raw provider payloads.
3. Fix an unrelated finding during a task only when it blocks or invalidates that task; otherwise register it here.
4. To resolve an item, move its row to [[Resolved Defects]] (top of the table) with the resolution date, root cause, fix, regression or direct verification, and PR. Update the living notes the fix changes.
